When Things Go Wrong, and What It Cost

Track A · lesson 0007 · about 20 minutes

A6 taught you to end finished sessions on purpose — and every session in A6 behaved. The missing case is the one that hurts: a session going bad mid-task. The reflex there is to keep correcting in place, because restarting feels like forfeiting the tokens you already spent. Notice what that reflex rests on: "restarting is cheaper" has been, so far, a claim you took on faith — and A3 taught you what claims are worth. This lesson closes the course with the two missing pieces: the signs that say stop now, and the bill that turns "cheaper" from faith into something you have read with your own eyes.

The warning signs

The primer told you the window degrades as it fills: the agent weighs more and attends less. Here is what degrading looks like from your side of the screen. Three signs, each one checkable:

  • The session forgets an instruction it was given. You said "change nothing in the tests" an hour ago, and the diff now touches a test. The instruction is still in the window — the session no longer attends to it.
  • The session repeats itself. It retries an approach you both already watched fail, or re-reads a file it read three turns ago, as if arriving for the first time.
  • The session states wrong things with confidence. "All tests pass now" — and nothing ran. A3 named this: claims are not evidence, and fluency is free. A failing window does not sound failing. It sounds exactly as sure as a healthy one.

Read the three signs as one message: the window, not the code, is the problem. That distinction decides everything you do next, because correcting in place adds more weight to the thing that is failing under weight. You cannot argue a window back to health — every correction is one more turn paying for the same degraded transcript.

The restart rule

So the rule: when the signs fire, restart with a better brief instead of arguing with a long session. The tokens already spent feel like a reason to stay. They are not. They are spent either way — no amount of staying brings them back. The only question a restart decides is where the next tokens go: into correction turns stacked on a transcript that taxes every one of them, or into a fresh window that reads the durable state and starts attending again.

The better brief is smaller than it feels. Everything A6 made you keep in files — the instructions file, the plan file, the save points — greets the new session for free. What is left is only what the failing session learned that never reached a file: what you asked for, which approach already failed, which decisions are already settled. Three sentences, sometimes three lines in the plan file. A restart is expensive exactly when you kept everything in the conversation — which is why the habits from A6 are what make this rule cheap to follow.

In the practice folder below, the reset is mechanical: restore your save point zero, or download the folder again for a factory-fresh copy. On real work, the save points are the reset. Either way the move is the same — good state from disk, better brief, fresh window.

Read the bill

One habit is still missing, and it is the one that makes the restart rule yours instead of this course's. The tool can show you two bills: what fills the window right now, and what the session has spent in total. Open them once per real session and the economics of this whole course stop being claims. You see the finished task still sitting in the window as dead weight. You see that your own typing is a sliver. You see what a restart would actually throw away — usually far less than it felt like.

Two readings matter more than any number on the screen. First: the biggest item is almost never your words or the agent's — it is what the tools brought back, the files read and the test output, because that is what the window is for. Second: part of the window was full before you typed a word. Your instructions file, the tool's own machinery — the fixed cost of opening a session. Small sessions pay it more often; long sessions pay the transcript tax instead. You have now seen both sides of that trade with your own eyes, which is the point.

The finale: one feature, every habit, then the bill

The practice folder below holds a small todo list, todo.py, with four passing tests in test_todo.py and a lean CLAUDE.md. The task, specified in README.md, is a sweep command with two decisions deliberately left open. Nothing about the task is new. That is the design: this is the course's closing exercise, and the work is to run every habit you have, start to finish, and then read what it cost.

The exercise — about fifteen minutes:

  1. Download and read. The button above saves the folder 0007-when-things-go-wrong. Read README.md: the sweep command, the fixed behavior, and the two open decisions. Notice the task passes A1's test — bounded scope, checkable outcome, small context footprint.
  2. Make save point zero. git init, add everything, commit. This is also your reset: if the warning signs fire later, you restore this point instead of arguing.
  3. Plan session (A2, A6). Start a session in the folder, in the mode that asks. One product: "Read README.md and write a plan for the sweep command to PLAN.md. Change nothing else." The plan must settle both open decisions and name the check command. Review it like A3 taught you, end the session, commit the plan.
  4. Build session. Start fresh: "Read PLAN.md and carry it out." Watch for the warning signs while it works — this is the session you would restart. Review the diff, then run python3 -m unittest -v: at least two new sweep tests, and the run ends OK. Claims are not evidence; the test run is.
  5. Read the bill before you end the session. Open the window bill and the spend bill, and write down three answers. One: which holds more tokens — what you typed, what the agent said, or what the tools brought back? Two: how much of the window did the whole build use, and how much was full before you typed a word? Three: name one thing in the window that lives in no file — that is what a restart brief would have had to carry. Your numbers are yours. This course publishes no expected range, and nobody is comparing.
  6. Commit the result. If anything went wrong on the way — a sign fired, you restored the save point, you restarted with a better brief — that was not the exercise failing. That was the exercise.

You can now scope a task to the window, plan before you build, match the mode to the risk, verify like the owner of the result, carry your setup in files, enforce your must-nevers, split work into small sessions, end a failing one early, and read the bill either way. The efficiency course starts from that bill and teaches you to shrink it on purpose: audit what loads into every session, keep the window lean, and size the model and its thinking to the task.

Quiz

  1. Mid-task, the session announces "all tests pass now" — and you saw no test run. What is this, and what do you do?

    A3's rule, now with teeth: fluency is free, so a degraded window sounds exactly as sure as a healthy one. Run the check yourself — and if the confident claim was false, count it as one of the three warning signs and weigh a restart.

  2. Which of these says the window — not the code, and not the task — is the problem?

    Questions, reading, and a first failed try are all healthy work. Repeating a failed approach as if arriving for the first time means the transcript is no longer being attended to — weight without attention, the primer's degradation showing up live.

  3. Forty minutes in, the signs are firing. Restarting feels like forfeiting everything spent so far. What do the spent tokens actually weigh in the decision?

    Spent tokens are spent, stay or go. The real comparison is about the next tokens: correction turns stacked on a transcript that taxes each one, versus a fresh window reading the durable state plus a three-sentence brief. The commits and files survive either way.

  4. You open the window bill after a normal build session. What usually holds the most tokens?

    Tool results dominate: file reads, test output, diffs. That is what the window is for — and it is why A6's helper idea and this lesson's restart rule both work, because the expensive part is reading, and reading can be re-done from disk by a fresh window.

  5. You decide to restart a failing session. What goes into the better brief?

    The files already brief the new session on everything durable — that was A6. Pasting the transcript imports the weight you restarted to shed. What is left is the delta the failing session learned: what you want, what failed, what is already decided. Usually three sentences.

Optional: at the end of your next real session, open both bills and ask the same three questions.
