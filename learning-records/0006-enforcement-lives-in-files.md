# Enforcement has moments, and it all lives in files

A5 closed record 0005's shaky item: the learner can now place a "must never happen" rule on the right side of the enforcement boundary. The evidence is a working guardrail, built by hand: the learner wired the finish moment to the test command, asked an unrelated question, watched the tool block the agent's finish while a test failed, and watched the same check clear once the program was fixed. The learner can state both tests for guardrail-shaped rules (must never happen, mechanically checkable) and the two honest limits (the check runs at every finish; the guardrail enforces the check, not the intent). On the add-on half, the learner judged one add-on against its standing cost — what it loads, when it loads, whether it earns its place — and learned that removing one after a fair reading is a pass.

Still shaky on: what actually carries between sessions. Everything the learner built in A4 and A5 — the instructions file, the settings, the guardrail — lives in files and greets every new session, yet the learner's reflex is still to keep one long session alive all day, because "it already knows the project." The learner has not yet separated the window (which dies with the session and degrades as it fills) from the durable state on disk (which does not), so ending a session still feels like losing work instead of shedding weight. A6 opens with a spaced callback to this item: everything that matters now lives in files — the session is the disposable part.
